# 第一阶段：画图

这是收益最高的一步。

你应该开始疯狂画图。

例如你的图片 AI 项目。

先画：

```text
用户
 ↓
Controller
 ↓
Service
 ↓
AI Gateway
 ↓
OpenAI / DeepSeek
```

然后继续细化：

```text
用户上传图片
 ↓
Controller
 ↓
校验参数
 ↓
存储 OSS
 ↓
生成 URL
 ↓
构造 Prompt
 ↓
调用模型
 ↓
返回结果
```

直到每一步你都知道：

* 输入是什么
* 输出是什么
* 为什么存在

---

你会发现：

很多以前不理解的东西突然明白了。

因为系统本质上就是：

> 数据流

---

# 第二阶段：追请求

这是我最推荐的方法。

不要看代码。

直接追一次请求。

例如：

用户发一句：

```text
帮我把这张图变成吉卜力风格
```

然后一路跟：

```java
PictureController
```

↓

```java
PictureService
```

↓

```java
AiImageService
```

↓

```java
OpenAiApi
```

↓

```java
HTTP请求
```

↓

```java
模型返回
```

↓

```java
数据库记录
```

↓

```java
前端展示
```

---

然后自己写一篇文档：

```text
一次生图请求是怎么执行的
```

甚至不用很专业。

能写出来就行。

# 第三阶段：给每个组件贴标签

例如：

### Redis

不要停留在：

```text
缓存
```

而是写：

```text
为什么需要 Redis？

因为 AI 接口昂贵。

同一个 Prompt 可能重复请求。

缓存后减少调用成本。
```

---

### OSS

不要停留在：

```text
存图片
```

而是：

```text
为什么不用数据库？

因为图片体积大。

数据库适合结构化数据。

对象存储更便宜。
```

---

### MQ

如果项目有 MQ：

```text
为什么需要 MQ？

生图耗时长。

用户不能一直等待。

异步执行更合理。
```

---

这一步实际上是在培养架构思维。

---

# 第四阶段：让 AI 当老师

这个特别适合你。

例如看到：

```java
ByteArrayResource
```

不要百度。

直接问：

```text
我是 Java 开发者。

请从 Spring 资源体系角度解释：

ByteArrayResource 是什么？

为什么这里不用 File？

为什么这里不用 MultipartFile？

在我的代码中的作用是什么？
```

---

或者：

```text
我给你发一个类。

请用面试官提问的方式给我讲解。

从：

- 功能
- 数据流
- 设计原因
- 可优化点

四个维度分析。
```

效果会特别好。

# 第五阶段：建立项目知识库

这是我觉得你最应该做的。

你本来就在做 RAG 项目。

不如拿自己项目练手。

建立一个：

```text
project-note
```

目录。

例如：

```text
01-整体架构.md

02-用户上传流程.md

03-AI对话流程.md

04-生图流程.md

05-RAG流程.md

06-Redis设计.md

07-OSS设计.md

08-数据库设计.md
```

每学懂一个点：

写进去。

---

三个月后你会得到一个东西：

```text
我项目的开发文档
```

这东西面试价值极高。

# 第六阶段：按照面试官思维拆项目

我建议你以后每天只做一个模块。

例如今天：

```text
RAG
```

你就问自己：

### 为什么要做 Query Rewrite？

### 为什么要做 Embedding？

### 为什么要做 Chunk？

### Chunk 多大合适？

### TopK 为什么是 5？

### 为什么不用全文检索？

### 向量数据库怎么工作的？

---

把这些问题一个个解决。

一个星期后：

你对 RAG 的理解会超过很多只会调用 LangChain 的人。

---

对于你当前的情况（Java 后端 + AI 应用开发方向），我会给你一个优先级：

1. **先彻底搞懂自己项目的数据流**
2. **再搞懂项目里每一个中间件存在的原因**
3. **再研究 AI 技术细节（RAG、Agent、Embedding 等）**
4. **最后才是研究复杂架构（DAG、工作流、MCP 等）**

因为面试时最容易被问死的，往往不是高深的 AI 理论，而是：

> 这个项目是你写的吗？
>
> 那你给我讲讲从用户点击发送到返回结果，中间发生了什么。

如果你能把这一条链路讲得清清楚楚，你的项目就已经从“Vibe Coding 项目”变成“真正属于你的项目”了。

结合你之前发给我的情况（图片平台 + AI 生图 + RAG 能力），我甚至建议你接下来一周暂停加新功能，专门做一件事：

**把项目的所有核心链路画成架构图，并为每条链路写一份时序文档。**

这件事对面试能力的提升，可能比再加三个新功能还大。
