# 10 — 响应规范设计

## BaseResponse — 统一响应包装

```java
@Data
@NoArgsConstructor  // ← 必须保留！否则 Jackson 反序列化失败
public class BaseResponse<T> implements Serializable {
    private int code;       // 0=成功，40xxx=客户端错误，50xxx=服务端错误
    private T data;         // 响应数据（错误时为 null）
    private String message; // "ok" / 错误信息
}
```

**为什么 HTTP 状态码始终 200？**
- 简化前端处理：不需要区分 HTTP 层错误和业务层错误
- 业务错误码更精细：40xxx/50xxx 比 HTTP 400/500 更有表达力
- 穿透代理/网关：某些网关会拦截非 200 响应

## ResultUtils — 响应构建工具

```java
ResultUtils.success(data)              // → {"code":0, "data":..., "message":"ok"}
ResultUtils.error(ErrorCode.XXX)       // → {"code":40000, "data":null, "message":"..."}
ResultUtils.error(code, "message")     // → {"code":xxx, "data":null, "message":"..."}
ResultUtils.error(ErrorCode, "自定义")  // → {"code":xxx, "data":null, "message":"自定义"}
```

## Controller 方法签名

```java
// 非流式 — 需要 BaseResponse 包装
@PostMapping
public BaseResponse<ChatResponseVO> chat(@Valid @RequestBody ChatRequest request)

// 流式 SSE — 不需要 BaseResponse（因为是一条条事件）
@PostMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<StreamEventVO> chatStream(@Valid @RequestBody ChatRequest request)
```

## ChatResponseVO — 统一聊天响应

```java
@JsonInclude(Include.NON_NULL)  // null 字段不序列化，响应更简洁
public record ChatResponseVO(
    String chatId,          // 会话ID（第一个响应中返回给前端）
    String type,            // chat / image_ready / image_analyzed / image_generated
    String message,         // AI 文本回复
    String imagePrompt,     // LLM 提取的生图提示词
    String style,           // LLM 识别的艺术风格
    String dimensions,      // LLM 建议的图片尺寸
    String revisedPrompt,   // 修订后的提示词（安全过滤后）
    String imageUrl,        // 生成的图片URL
    String imageBase64,     // 生成的图片base64
    Object ragDebugInfo     // RAG 调试信息 { explicit, retrieved, template }
) {}
```

**静态工厂方法**（不同模式构造不同字段组合）：
- `objToVo(ImageAgentResponse, chatId)` — LLM 输出 → VO
- `textOnly(chatId, text)` — 纯文本回复
- `imageAnalyzed(chatId, result)` — 分析结果
- `imageGenerated(...)` — 生成结果（5个重载，覆盖不同参数组合）

## StreamEventVO — SSE 流事件

```java
public record StreamEventVO(
    String type,         // chatId / token / progress / done / error
    String chatId,       // 会话ID
    String content,      // 流式文本片段
    ChatResponseVO data  // 完整数据（done 事件中返回）
) {}
```

**SSE 流事件序列**：
```
event: chatId    → { "type":"chatId", "chatId":"uuid-xxx" }
event: token     → { "type":"token", "content":"好" }
event: token     → { "type":"token", "content":"的" }
event: token     → { "type":"token", "content":"，" }
...
event: progress  → { "type":"progress", "content":"正在生成图片..." }
event: done      → { "type":"done", "chatId":"uuid-xxx", "data":{...} }
```

## 分层规范

| 层 | 返回类型 | 是否包装 BaseResponse |
|----|---------|---------------------|
| Controller | `BaseResponse<VO>` 或 `Flux<StreamEventVO>` | ✅ Controller 包装 |
| App/Service | 裸 VO | ❌ 不包装 |
| Advisor | `AdvisedResponse` / `Flux<AdvisedResponse>` | ❌ 不包装 |

**核心原则**：`BaseResponse` 是 HTTP 层的概念，只在 Controller 层使用。下层返回业务对象，由 Controller 统一包装。

## 请求体规范

- 始终 POST + `@RequestBody`（不通过 URL 传内容）
- 使用 `@Valid` 触发 Jakarta Bean Validation
- `ChatRequest` 用 Java record 保证不可变性

```java
@PostMapping
public BaseResponse<ChatResponseVO> chat(@Valid @RequestBody ChatRequest request)
```
