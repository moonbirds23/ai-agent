# 扩展方向总览

## 已规划的扩展

### 1. 图生图模型接入

当前是图→文→图，计划接入混元等图生图模型实现真正的图→图。
- 详情: [图生图接入方案](图生图接入方案.md)
- 状态: 方案已设计。Phase 1 已完成画像同步化（消除重复视觉调用），为图生图接入清理了前置障碍

### 2. COS 对象存储迁移

当前默认 Local 存储，COS 实现已预留（`CosObjectStorageService` + `@Profile("cos")`）。
- 需要: COS SDK 配置、Bucket 策略、URL 签名
- 状态: 接口已抽象，实现预留

### 3. 多模型支持

当前全链路智谱，可扩展为：
- 多 Provider 切换（OpenAI / 智谱 / DeepSeek / 混元）
- 按模型能力自动路由（生图用混元，文本用 DeepSeek，视觉用智谱）
- 状态: 未开始

### 4. 真实多用户支持

当前 `user_id` 硬编码为 1L，单用户模式。
- 需要: 用户认证、多租户隔离、权限控制
- 状态: 数据库字段已预留（user_id, space_id）

### 5. 前端增强

- 图片编辑/裁剪
- 批量操作（批量收藏、批量删除）
- 生图历史画廊

### 6. 内容安全增强

当前 `ContentGuardAdvisor` 只有字面关键词匹配。
- 需要: 接入独立安全模型（DeepSeek 等）做语义审核
- 状态: Phase 2 已完成 Query Rewrite 提示注入防护（XML 标签包裹）。语义审核仍需要独立安全模型

### 7. 可观测与指标 (Phase 4 预留)
- RAG Trace 持久化到 PG + 仪表板
- 核心链路指标（检索耗时、重排分布、生图失败率、向量写入失败数）
- 异步画像补偿重试定时任务
- Docker Compose 本地开发环境

## 架构预留的扩展点

### ImageGenerationService 接口

不同生图模型只需实现接口：

```java
public interface ImageGenerationService {
    ImageGenerationResult generate(ImageGenerationRequest request);
    String getProviderName();
}
```

已有实现: `ZhipuImageGenerationService` (CogView)，可新增 `HunyuanImageGenerationService` 等。

### ObjectStorageService 接口

```java
public interface ObjectStorageService {
    StoredObject upload(byte[] bytes, String key, String contentType);
    byte[] download(String key);
    void delete(String key);
    String getUrl(String key);
}
```

通过 `@Profile` 切换: `@Profile("!cos")` → Local, `@Profile("cos")` → COS。

### VectorIndexService 接口

```java
public interface VectorIndexService {
    void upsertPictureVector(Long pictureId, String indexText, Map<String, Object> metadata);
    void deletePictureVector(Long pictureId);
    List<VectorSearchHit> search(String query, int topK, double minScore);
}
```

当前: `PgVectorIndexService` (pgvector)。可扩展到 `MilvusVectorIndexService`、`QdrantVectorIndexService` 等。

### Advisor 链

通过 `getOrder()` 控制顺序。新增 Advisor 只需实现 `CallAdvisor` / `StreamAdvisor` 接口并注册到 ChatClient 的 defaultAdvisors。
