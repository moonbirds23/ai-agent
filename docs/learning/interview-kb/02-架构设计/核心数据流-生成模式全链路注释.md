## RAG 数据类型退化链（关键！）

```
GalleryPicture (24字段: id, url, name, tags, picFormat, picHash...)
  │  // 完整的图片元数据和对象存储引用
  ▼
ReferencePicture = { GalleryPicture picture, PictureAiProfile profile }
  │  // 图片 + AI画像，数据完整
  │  // explicitReferences / retrievedReferences
  ▼ ★ 退化点1: RagContextPackerImpl.pack()
PackedRagContext = { String explicitText, String retrievedText, String templateText, int totalChars }
  │  // ★ ReferencePicture → 格式化纯文本，url/id/format 全部丢失
  ▼ ★ 退化点2: PromptReferenceAssembler.assemble()
String augmentedMsg
  │  // PromptTemplate 渲染为完整 Prompt 字符串
  ▼ ★ 退化点3: ChatServiceImpl.prepareRagContext()
RagPrepared { String originalMsg, String augmentedMsg, Object debugData }
  │  // 纯文本载体
  ▼ ★ 退化点4: ChatServiceImpl.handleGeneration() L240
imageGenerationService.generate(String prompt, String style, String dimensions)
  // ★ GalleryPicture 在作用域内但未被传入！图片二进制从未到达生图API
```

**这就是当前架构的本质：图→文→图。** 图片信息经过 4 次退化最终变成纯文本，生图模型只收到 LLM 的文字描述。

## Phase 1-3 改动对数据流的影响

| 步骤 | 改动 | 影响 |
|------|------|------|
| ③ | 画像分析异步→同步 | 去掉了 publishEvent+@Async，入库后立即分析 |
| ④-L2 | Rerank 归一化 | 关键词分不再碾压语义分 |
| ⑤ | ExceptionGuard order MIN | 所有 Advisor 异常被兜底 |
| ⑤ | RagInjection 替换逻辑 | 历史消息不被覆盖 |
| ⑤ | 流式路径补 RAG 参数 | 流式生图不再丢失 RAG |
| ⑥ | CogView API 加 @CircuitBreaker | 熔断保护 |
