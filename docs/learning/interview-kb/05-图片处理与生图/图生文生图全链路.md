# 图→文→图全链路

## 链路概览

当前生图本质上是 **图→文→图** 的间接路径：

```
用户参考图 ──→ Vision(glm-4.5v) ──→ 文本特征 ──→ 向量检索 ──→ 文本参考
    │                                                           │
    └───→ LLM(glm-4-flash) 看图 ──→ imagePrompt 文本 ──→ CogView ──→ 生成图
                                            ↑                      ↑
                                    纯文本描述              纯文本调用，无图输入
```

LLM 充当了"图→文翻译器"，把视觉信息转译成文字，生图模型再"文→图"。信息保真度依赖 LLM 的描述能力。

## 图片串联全流程

### 1. 前端 → 后端

```
FileReader.readAsDataURL(file)
  → "data:image/png;base64,iVBORw0KGgo..."
  → ChatRequest.imageBase64
```

### 2. 自动入库

```java
// ChatServiceImpl.autoSaveToCacheGallery()
GalleryUploadRequest uploadReq = new GalleryUploadRequest(
    imageBase64, "chat-image-" + System.currentTimeMillis(),
    null, null, null, null,
    StorageLocation.CACHE       // ★ 缓存位置，7天后自动清理
);
GalleryPicture saved = galleryService.upload(uploadReq);
```

**Phase 1 修复：downloadPicture 死循环** — `tryExt` 变量未使用，循环7次下载同一key。已简化为单次下载。

**Phase 1 修复：画像分析同步化** — `@Async` 事件改为入库后同步分析，消除同一张图调两次视觉模型。`PictureAutoAnalysisListener` 改为补偿扫描器（定时重试 vector_status=-2 的记录）。

### 3. 构建 Media（发给 ChatClient）

```java
// buildGenerationUserSpec()
spec.text(originalMsg);        // 用户原始消息
if (savedPicture != null) {
    spec.media(new Media(mime, savedPicture.url().toURI()));
    // ★ 已入库 → 用图库URL → ChatMemory 可识别为 GALLERY
} else {
    spec.media(new Media(MimeTypeUtils.IMAGE_PNG, new ByteArrayResource(bytes)));
    // ★ 未入库 → 直接发 base64 bytes
}
```

**Phase 1 修复：MIME 类型动态解析** — `buildUserSpec()` 降级路径从硬编码 `IMAGE_PNG` 改为 `extractFormatFromBase64()` 从 data URL 解析实际格式，`extractFormatFromUrl()` 从 URL 后缀推断。

### 4. ChatMemory 图片序列化

**存入** (`toRecord()`)：
```
Media.getData() 是 URI → extractGalleryPictureId(uri):
  匹配 /gallery/files/123 → ImageRef.gallery(123)
  不匹配 → visionAnalysis → ImageRef.textDescription("故宫角楼，对称构图...")

Media.getData() 是 ByteArrayResource → visionAnalysis → ImageRef.textDescription(...)
```

**还原** (`toMessage()`)：
```
GALLERY: galleryService.getById(123) → storageService.download(storageKey) → Media
TEXT_DESCRIPTION: "用户在此前的对话中发过图片，图片描述：故宫角楼..."
```

### 5. 生图调用

```java
ImageGenerationResult genResult = imageGenerationService.generate(
    aiResp.imagePrompt(),    // "雪后故宫角楼，朱红城墙覆白雪，对称构图，写实摄影风格"
    aiResp.style(),          // "写实摄影"
    aiResp.dimensions()      // "1024x1024"
);
// ★ saved(GalleryPicture) 在作用域内但未被传入
```

**Phase 2 修复：外部图片 URL 处理** — `ZhipuVisionAnalysisService` 收到 imageUrl 时改为服务端通过 `ImageDownloadService` 下载后以 base64 传入智谱，消除间接 SSRF。

**Phase 2 修复：图片 URL 导入 SSRF** — `CogViewImageApi.download()` 的重定向目标也做 SSRF 校验（validateUri 内部调用 validateHost）。

### 6. 尺寸标准化

```java
// ZhipuImageGenerationService.normalizeSize()
"16:9" / "landscape"  → "1344x768"
"9:16" / "portrait"   → "768x1344"
"1:1" / "square"      → "1024x1024"
自定义宽高 → normalizeByRatio(按比例归一到三种标准尺寸)
```

## 生成图回存图库（可选）

```java
if (saveGeneratedToGallery == true):
    → galleryService.upload(base64, name=imagePrompt, category="ai-generated", MAIN)
    或 galleryService.importUrl(url, ...)
    → 异步触发 AI 画像分析（与手动上传流程一致）
```

## 瓶颈分析

1. **串行依赖**: autoSave → RAG → ChatClient(LLM) → ImageGen(CogView)，三个步骤无法并行
2. **中间损耗**: 图片信息经 LLM 转译成文字后再传给生图模型，色彩/构图细节可能失真
3. **图片数据被丢弃**: `saved` (GalleryPicture) 在生图调用时未被使用，图片二进制只在 LLM(看图)阶段有用
