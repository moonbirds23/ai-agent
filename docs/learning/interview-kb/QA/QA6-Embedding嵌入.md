# 在 RAG 中的 Embedding 嵌入是什么？

> 标签: RAG, Embedding, 向量化 | 难度: 🟢 简单 | 编号: QA6

---

## 一句话定义

**Embedding（嵌入/向量化）** 是把文本、图片等非结构化数据，通过专门的模型映射为一串固定长度的数字（向量），使得语义相近的内容在向量空间中距离也相近。

---

## 为什么叫"嵌入"

把高维、稀疏的原始数据（一段文字可能有几千个汉字，每个字都是独立的符号）"嵌入"到一个低维、密集的连续向量空间中。

```
原始文本: "赛博朋克风格的夜景，霓虹灯闪烁的街道"
    ↓ Embedding 模型
向量: [0.23, -0.45, 0.78, 0.12, -0.33, ..., 0.56]   ← 1024个浮点数
```

每个维度编码了一种语义特征：颜色倾向、风格类型、情感色彩、主题类别。

---

## 核心特性：语义相近 = 向量相近

```
文本 A: "一只猫坐在沙发上"     → [0.12, 0.34, ..., 0.78]
文本 B: "猫咪趴在沙发上面"     → [0.11, 0.36, ..., 0.76]  ← 距离近
文本 C: "今天天气真不错"       → [0.89, -0.23, ..., -0.15] ← 距离远
```

不需要精确关键词匹配——"猫"和"猫咪"在向量空间里天然就是邻居。

---

## 在 RAG 中的位置

```
离线阶段（建库）:
  文档 → Embedding 模型 → 向量 → 向量库

在线阶段（检索）:
  用户查询 → 同一个Embedding模型 → 向量 → 向量库中搜最近邻
```

**关键约束**：两次必须用同一个模型。不同模型向量空间不同，跨模型算相似度没有意义。

---

## 常见 Embedding 模型

| 模型 | 维度 | 最大输入 | 中文支持 | 特点 |
|------|------|---------|---------|------|
| OpenAI text-embedding-3-small | 512/1536 | 8191 token | 中 | 性价比高 |
| OpenAI text-embedding-3-large | 1024/3072 | 8191 token | 中 | 精度最高 |
| 智谱 embedding-2 | 1024 | 512 token | **优** | 中文场景首选 |
| BGE-large-zh | 1024 | 512 token | **优** | 开源，可本地部署 |
| BGE-M3 | 1024 | 8192 token | **优** | 多语言，长文本 |
| E5-large-v2 | 1024 | 512 token | 中 | 英文场景好 |

---

## 选型考量

| 维度 | 考量点 |
|------|--------|
| **语言** | 中文场景优先选中文优化模型（智谱/BGE） |
| **维度** | 越高越精细，存储检索成本也越高。1024 是常用平衡点 |
| **输入长度** | 512 vs 8192 token。长文本必须选支持长输入的 |
| **成本** | 云端 API（按 token 计费）vs 本地部署（GPU 成本） |
| **一致性** | 选定不能轻易换——换了整个向量库要重建 |

---

## 面试速记

> Embedding = 把文字变成一串数字，语义相近的数字也相近。
>
> RAG 中出现两次：建库 + 查询，必须用同一个模型。
>
> 选型三要素：语言匹配度、维度成本、输入长度限制。
