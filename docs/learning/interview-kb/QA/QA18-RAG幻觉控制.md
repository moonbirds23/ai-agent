# 如何减少 RAG 系统的幻觉问题？有哪些实用方法？

> 标签: RAG, 幻觉控制, 生成可信度 | 难度: 🟡 中等 | 编号: QA18

---

## 一、一句话回答

减少 RAG 幻觉不能只依赖 Prompt，而要建立一条从数据治理、检索召回、上下文构造、证据约束生成到生成后校验的全链路防护机制。核心原则是：有证据才回答，证据不足就触发检索失败保护或降置信处理，避免无证据生成。

---

## 二、RAG 幻觉的主要来源

RAG 可以降低模型幻觉，但不会自动消除幻觉。常见来源包括：

| 来源 | 典型问题 | 结果 |
|------|----------|------|
| 知识库质量差 | 文档过期、重复、错误、格式噪声多 | 模型基于错误材料生成错误答案 |
| 检索召回不足 | 没检到关键文档，或相关文档排名靠后 | 模型在证据不足时产生无证据生成 |
| 上下文噪声注入 | Top-K 中混入大量无关 chunk，或上下文边界不清 | 模型忽略关键证据、混淆来源或错误拼接 |
| 生成约束弱 | 未要求基于证据回答，也没有拒答策略 | 模型补充资料外事实，产生看似合理但无依据的结论 |
| 引用校验缺失 | 模型输出不存在或不支撑结论的引用 | 形成“有引用但不可信”的答案 |

因此，幻觉控制要分层治理，而不是在最后简单追加一句提示词约束。

---

## 三、基础必做项：主流 RAG 系统的默认防护

### 3.1 提升知识库质量

入库前需要做数据清洗、结构化和质量控制：

- 清理 HTML 噪声、页眉页脚、乱码、广告文本；
- 删除重复文档和近重复 chunk；
- 过滤过期、无效或低可信来源；
- 保留标题、章节、页码、URL、更新时间、权限、业务标签等元数据；
- 对 FAQ、表格、代码、图片 OCR 等特殊内容采用专门解析策略。

如果知识库本身存在错误，RAG 会把错误内容包装成“有证据的错误答案”，比普通幻觉更难排查。

### 3.2 合理分块和元数据保留

分块过大容易带入无关内容，分块过小又可能丢失上下文。常见做法是：

- 按标题、段落、语义边界切分；
- 设置适度 chunk overlap，避免跨段信息断裂；
- 保存章节路径和相邻 chunk 信息；
- 对结构化内容保留表头、字段名和单位。

分块策略会直接影响召回质量、上下文可读性和引用可验证性。

### 3.3 Query Rewrite / Query Expansion

用户问题可能很短、含糊或依赖上下文，例如“它怎么优化？”。检索前应将问题改写为更完整的检索表达：

```text
原始问题: 它怎么优化？
改写后: RAG 系统如何通过检索增强、重排序和上下文压缩进行优化？
```

这样可以降低“查询表达不清 → 检索失败 → 无证据生成”的风险。

### 3.4 混合检索

单纯向量检索擅长语义泛化，但可能漏掉专有名词、编号、代码符号和精确短语；关键词检索擅长精确匹配，但语义泛化能力有限。主流工程实践常采用混合检索：

```text
向量检索 Top-K + BM25/关键词检索 Top-K → 合并去重 → Rerank
```

该方案可以同时覆盖语义相似和精确匹配，降低漏召回导致的幻觉风险。

### 3.5 相似度阈值与检索失败保护

不应无条件把 Top-K 全部注入上下文。低相关候选应被过滤：

```text
if similarity_score < threshold:
    不注入该文档
```

如果过滤后没有足够证据，应触发检索失败保护：

```text
基于当前知识库，我无法确定答案。
```

阈值需要结合 Embedding 模型、距离度量、业务数据和离线评测确定，不能直接复用其他项目的固定分数。

### 3.6 Rerank 精排

初检阶段通常追求召回，允许候选集中存在噪声；Rerank 阶段负责从候选中选出真正相关的证据。

常见方式：

- 规则加权：向量分、关键词分、元数据分、时间衰减分；
- Cross-Encoder：对 query-document pair 做精细相关性判断；
- LLM-as-Reranker：让 LLM 判断候选相关性，适合复杂语义但成本较高。

Rerank 是减少上下文噪声注入的重要手段，但它不能弥补初检阶段完全漏召回的关键文档。

## 四、上下文构造：减少噪声和边界混淆

### 4.1 明确上下文边界

检索内容应使用结构化标签包裹，避免模型混淆系统指令、用户问题和检索资料：

```xml
<retrieved_context id="1" source="doc-1" score="0.87">
这里是检索到的文档内容……
</retrieved_context>
```

Prompt 中应明确：回答只能基于 `<retrieved_context>` 中的证据。

### 4.2 上下文压缩

检索到的文档不宜原样全部注入 Prompt。需要去重、截断和抽取相关句子：

```text
检索文档 → 去重 → 摘取相关句子 → 控制总长度 → 注入 Prompt
```

这样可以降低上下文噪声注入，也能缓解长上下文中的 “Lost in the Middle” 问题。

### 4.3 保留来源信息

每个 chunk 应携带文档名、URL、页码、章节、更新时间和业务库标识等来源信息。生成答案时要求引用来源，可以增强可验证性，并约束模型围绕证据组织答案。

---

## 五、生成阶段：证据约束与拒答策略

### 5.1 明确证据边界

Prompt 中应明确模型只能基于检索资料回答：

```text
请仅基于参考资料回答。
如果参考资料中没有足够证据，请回答：
“基于当前知识库，我无法确定答案。”
不要生成未被参考资料支持的事实。
```

这不是单纯要求模型“少犯错”，而是把生成边界限定在可验证证据内。

### 5.2 要求答案引用证据

引用可以提高可验证性，并让模型更倾向于围绕检索材料组织答案：

```text
Spring AI 的 Advisor 链可以在调用前后拦截请求 [1]。

引用：
[1] Spring AI Reference，ChatClient Advisors 章节
```

引用并不能完全消除幻觉，因为模型可能引用不支撑结论的来源；因此高可信场景还需要引用校验。

### 5.3 限制资料外推断

生成约束可以要求模型区分不同置信等级：

- “资料明确说明”；
- “资料间接支持”；
- “当前资料不足，无法确定”；
- “不同来源存在冲突”。

这样比让模型直接给出确定答案更稳健。

## 六、高可信增强项：适用于严肃场景

### 6.1 断言抽取 + 反向验证

对高风险场景，可以将答案拆成事实断言，再回到知识库验证每个断言是否有证据支持：

```text
答案 → 抽取核心断言 → 对每个断言检索证据 → 无证据则删除、改写或标低置信度
```

该方案可以提高可信度，但会增加额外模型调用和延迟，适合法务、医疗、金融、合规、生产运维等场景。

### 6.2 引用支撑校验

不仅检查引用编号是否合法，还要判断引用 chunk 是否真的支持答案句子：

```text
答案句子 + 引用 chunk → 判断是否支持 / 部分支持 / 不支持
```

如果不支持，应删除引用、重新生成答案或提示低置信度。

### 6.3 LLM Critic / 自检

使用第二轮模型调用检查：

- 答案中哪些句子缺少上下文支持；
- 是否引用了不存在的来源；
- 是否把多个文档的信息错误拼接；
- 是否忽略了证据冲突。

该方法对复杂答案有效，但成本较高，且 Critic 本身也可能出错，因此更适合作为增强校验，而非唯一保障。

### 6.4 人工反馈闭环

对用户点踩、人工纠错、低置信回答和空检索案例进行记录，反向优化：

- 补充缺失文档；
- 调整分块策略；
- 调整 Top-K、阈值和索引参数；
- 优化 Rerank 权重；
- 增加领域同义词和查询改写规则。

## 七、面试回答模板

> 减少 RAG 幻觉要做全链路治理。基础层面，先保证知识库质量，做好清洗、去重、分块和元数据标注；检索层面，通过 Query Rewrite、混合检索、相似度阈值和 Rerank 提升相关证据召回，避免上下文噪声注入；上下文层面，对检索内容做边界标记、去重和压缩，保留来源信息；生成层面，要求模型只基于证据回答，资料不足时触发检索失败保护或拒答，并输出引用。对于高可信场景，还可以增加断言抽取、反向验证、引用支撑校验和人工反馈闭环。总结来说，RAG 防幻觉的关键不是让模型“自由发挥得更谨慎”，而是让系统保证“有证据才回答，无证据就拒答或降置信”。

## 八、追问点

**Q: RAG 一定能解决大模型幻觉吗？**

> 不能。RAG 可以通过外部知识降低无依据生成的概率，但如果知识库过期、检索结果不相关、上下文噪声过多，仍然可能产生错误答案，甚至产生“有引用但不被引用内容支持”的错误答案。

**Q: 如果检索不到内容怎么办？**

> 应触发检索失败保护，例如明确回答“基于当前知识库无法确定”，或引导用户补充问题条件。高可信场景不应让模型基于通用知识直接补全答案，除非产品明确允许并标注为非知识库来源。

**Q: Top-K 越大越能减少幻觉吗？**

> 不一定。Top-K 太小容易漏召回，Top-K 太大又会引入噪声。常见做法是初检取较大的候选集，再经过 Rerank、去重和上下文压缩后，只注入最相关的少量证据。

**Q: 强制引用能完全避免幻觉吗？**

> 不能。模型可能输出合法编号但引用内容并不支撑答案，所以强制引用需要配合引用编号校验、断言验证和前端可点击溯源，才能真正提升可信度。

## 九、项目实践参考

在当前 `ai-agent` 项目里，可以对应到以下实践：

- Query Rewrite：结合对话历史补全用户真实检索意图；
- Hybrid Retrieval：向量检索 + 关键词/元数据召回；
- Rerank：对 vectorScore、keywordScore、metadataScore 归一化后加权排序；
- Context Pack：按 `referenceMode` 裁剪字段，并限制注入 Prompt 的上下文长度；
- Rag Trace：记录检索、重排、压缩链路，便于排查幻觉来源。
