# 在 RAG 中，常见的分块策略有哪些？分别有什么区别？

> 标签: RAG, 索引, 分块 | 难度: 🟢 简单 | 编号: QA5

---

## 一、一句话总结

分块策略的核心目标是**在检索精度和上下文完整性之间找到平衡**。块太大 → 检索不准；块太小 → 语义碎片化。

---

## 二、策略详解与对比

### 策略 1：固定大小分块（Fixed-Size）

按固定字符数或 Token 数切分，不考虑语义。

```
例：每 100 字一刀，不管句子是否被切断
```

| 优点 | 缺点 |
|------|------|
| 实现最简单，`text[0:500],[500:1000]...` | 可能切在句子/词语中间 |
| 并行处理快 | 语义完整性最差 |

**适用**：快速原型、对语义完整性要求不高的场景。

### 策略 2：递归分块（Recursive Chunking）

按分隔符优先级逐级切割：`段落 → 句子 → 逗号 → 字符`。先尝试按大边界切，太长的再按小边界切。

```
段落太长？→ 按句子切
句子还太长？→ 按逗号切
逗号还太长？→ 按字符硬切
```

| 优点 | 缺点 |
|------|------|
| 尽量保持语义边界 | 实现比固定大小复杂 |
| 自适应文档结构 | 分隔符需根据语言调整（中文句号 vs 英文句号） |

**适用**：通用场景，LangChain `RecursiveCharacterTextSplitter` 的默认策略。

### 策略 3：语义分块（Semantic Chunking）

用 Embedding 模型计算相邻句子的语义相似度，在"语义突变点"切开。

```
句子1: "Transformer的核心是注意力机制"    ─┐ 语义相似度 0.85 → 合并
句子2: "自注意力让模型关注输入的不同部分"  ─┘
句子3: "训练需要大量GPU资源"              ← 相似度 0.3 → 在此切开
```

| 优点 | 缺点 |
|------|------|
| 语义最连贯，分块质量最高 | 需要额外计算所有相邻句子的 Embedding |
| 自然贴合文档的逻辑结构 | 长文档计算量大 |

**适用**：对检索精度要求高的场景，文档结构不规则时。

### 策略 4：固定大小 + 重叠（Overlap）

固定大小切分，但相邻块之间设置 10%~20% 的重叠区域。

```
无重叠:
  Chunk1: "...深度学"
  Chunk2: "习是机器学习的..."          ← 关键信息被切在边界

有重叠 (20%):
  Chunk1: "...人工智能。深度学"
  Chunk2: "人工智能。深度学习是..."     ← 重叠区域兜底
```

| 优点 | 缺点 |
|------|------|
| 防止关键语义落在边界上 | 重叠部分占额外存储 |
| 实现简单，效果好 | 检索到的相邻块内容有重复 |

**适用**：实际生产中最常用的策略，常与递归分块组合使用。

### 策略 5：按结构分块（Structural Chunking）

按文档的结构标记分块：Markdown 标题、HTML 标签、代码函数边界、数据库 schema 边界等。

```
Markdown:
  # 标题1 → Chunk 1
  ## 子标题 → Chunk 2
  # 标题2 → Chunk 3
```

| 优点 | 缺点 |
|------|------|
| 语义边界最清晰 | 只适用于有明确结构的文档 |
| 每个块自包含（标题+内容） | 结构不规则时回退到其他策略 |

**适用**：技术文档、API 手册、结构化知识库。

---

## 三、五种策略对比总览

| 策略 | 语义完整性 | 实现复杂度 | 是否需 Overlap | 代表场景 |
|------|-----------|-----------|---------------|---------|
| 固定大小 | ⭐ | ⭐ | 建议加 | 快速原型 |
| 递归分块 | ⭐⭐⭐ | ⭐⭐ | 建议加 | 通用文档 |
| 语义分块 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 不需要 | 高质量检索 |
| 固定+Overlap | ⭐⭐ | ⭐⭐ | 内置 | 生产最常用 |
| 按结构分块 | ⭐⭐⭐⭐ | ⭐⭐ | 不需要 | 技术文档 |

---

## 四、关键参数

| 参数 | 建议值 | 说明 |
|------|--------|------|
| chunk_size | 256~512 token（中文约 200~400 字）| 块大小 |
| chunk_overlap | 10%~20% | 重叠比例 |
| 分隔符优先级 | `\n\n` → `。` → `；` → `，` → 字符 | 递归分块用 |
| 单块上限 | 不超过 Embedding 模型输入限制 | embedding-2: 512 token |

---

## 五、面试速记

> 分块策略五个等级，从粗到精：
> - 固定大小：最简单，切在词中间
> - 递归分块：按分隔符逐级切，LangChain 默认
> - 固定+Overlap：最实用，生产标配
> - 语义分块：质量最高，但慢
> - 按结构分块：有标题/章节时最好用
>
> 没有银弹，取决于文档类型。实际项目通常是"递归分块 + Overlap + 合理大小"组合。
