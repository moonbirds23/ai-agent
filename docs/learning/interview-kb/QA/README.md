# QA 目录

本目录存储 RAG 面试题库，每题一个独立文件。

## 回答风格规范

生成和整理面试回答时，默认采用**严谨、专业、工程化**的表达风格。

- 可以保持易理解，但不要过度口语化、故事化或“哄小白式”表达
- 优先使用准确术语，例如：召回、精排、元数据、上下文压缩、证据支撑、引用校验
- 解释概念时先给专业定义，再用简短例子辅助理解
- 面试回答模板要像候选人在技术面中作答，而不是像科普文章
- 对不确定或有前提限制的结论，要说明适用条件，避免绝对化表达
- 需要体现工程落地意识：链路、边界、权衡、风险、兜底策略
- 鼓励引用权威来源，包括技术官方文档、框架文档（如 Spring AI、LangChain、OpenAI/Anthropic/Zhipu 文档等）以及经典论文，并在合适位置标注出处或来源说明
- 技术栈和实现方法优先选择**主流、常见、面试认可度高**的方案，再补充少量新颖或实用的扩展方案，避免为了“炫技”引入冷门实现
- 对方案选型要说明为什么常用、适合什么场景、有什么局限；如果提到新颖方案，要明确它是增强项而非默认方案

核心原则：**易懂但不低幼，清晰但不牺牲专业性；以主流工程实践为主体，以权威来源和适度前沿方案增强可信度。**

## 标准题目结构建议

每题不要求机械套模板，但建议至少覆盖以下信息：

1. **核心结论 / 专业定义**：先给可直接面试复述的结论，再展开解释。
2. **主流实现方案**：优先讲生产中最常见、可落地、面试认可度高的方案。
3. **工程落地要点**：说明链路、边界、性能、成本、数据质量、可观测性和兜底策略。
4. **增强方案 / 前沿补充**：只补充少量实用增强项，并说明适用条件和额外代价。
5. **常见误区 / 追问点**：指出容易绝对化、概念混淆或工程不可落地的说法。
6. **面试回答模板**：保持 2~5 分钟可讲清楚，体现主流方案、边界和取舍。
7. **参考来源 / 延伸阅读**：优先引用论文、官方文档、Spring AI / LangChain / LlamaIndex / pgvector 等主流文档。
