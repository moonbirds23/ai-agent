# 余弦相似度、欧几里得距离和曼哈顿距离分别是什么？有什么区别？

> 标签: 向量数据库, 相似度, 距离度量 | 难度: 🟢 简单 | 编号: QA15

---

## 一、核心公式

### 1.1 余弦相似度（Cosine Similarity）

余弦相似度衡量两个向量方向的一致程度，通常用于关注语义方向而非向量模长的场景。

```text
cos(A, B) = (A · B) / (|A| × |B|)
          = Σ(A_i × B_i) / (√ΣA_i² × √ΣB_i²)

取值范围: [-1, 1]
  1  → 方向完全相同
  0  → 近似正交
 -1  → 方向相反
```

在一些向量数据库中会使用“余弦距离”表示排序方向，例如：

```text
cosine_distance = 1 - cosine_similarity
```

因此实现时要区分“相似度越大越相似”和“距离越小越相似”。

### 1.2 欧几里得距离（Euclidean Distance / L2 Distance）

欧几里得距离衡量两个向量在多维空间中的直线距离，关注绝对坐标位置。

```text
d(A, B) = √Σ(A_i - B_i)²

取值范围: [0, +∞)
  0 → 两个向量位置完全相同
  值越大 → 距离越远
```

### 1.3 曼哈顿距离（Manhattan Distance / L1 Distance）

曼哈顿距离衡量各维度坐标差的绝对值之和，也称 L1 距离。

```text
d(A, B) = Σ|A_i - B_i|

取值范围: [0, +∞)
  0 → 两个向量位置完全相同
  值越大 → 距离越远
```

## 二、几何直觉

```text
二维空间中，A = (3, 0), B = (3, 4):

欧几里得距离: √((3-3)² + (0-4)²) = 4      关注直线距离
曼哈顿距离:   |3-3| + |0-4| = 4           关注坐标轴方向累计距离
余弦相似度:   (3×3 + 0×4) / (3×5) = 0.6   关注方向夹角

A = (3, 0), C = (6, 0):

欧几里得距离: 3
余弦相似度:   1.0

解释：A 和 C 方向完全相同，但模长不同。余弦认为二者方向一致，欧几里得会认为二者仍有空间距离。
```

## 三、核心区别

| 维度 | 余弦相似度 | 欧几里得距离 | 曼哈顿距离 |
|------|------------|--------------|------------|
| 衡量对象 | 向量方向/夹角 | 空间直线距离 | 各维度绝对差累计 |
| 是否受模长影响 | 通常不敏感 | 敏感 | 敏感 |
| 排序含义 | 相似度越大越相似；余弦距离越小越相似 | 距离越小越相似 | 距离越小越相似 |
| 常见使用 | 文本语义检索、归一化 Embedding | 坐标、连续特征、部分图像/多模态向量 | 稀疏特征、逐维差异敏感场景 |
| 向量库支持 | pgvector 支持 cosine distance | pgvector 支持 L2 distance | pgvector 支持 L1/taxicab distance（具体以版本为准） |

## 四、为什么文本 Embedding 常用余弦相似度

文本 Embedding 的语义相近性通常更多体现在向量方向上，而不是原始模长上。余弦相似度会消除模长影响，更适合比较“语义方向是否接近”。

```text
“人工智能” → Embedding A → 模长较大
“AI”       → Embedding B → 模长较小

欧几里得距离可能受模长差异影响较大；
余弦相似度更关注二者是否指向相近语义区域。
```

但这个结论也有前提：不同 Embedding 模型的训练目标不同，有些模型推荐使用 cosine，有些推荐使用 dot product 或在向量归一化后使用 inner product。工程上应优先遵循模型官方说明和向量数据库的距离度量配置。

当前项目使用 pgvector 的余弦距离配置：

```yaml
spring.ai.vectorstore.pgvector.distance-type: cosine_distance
```

## 五、主流选择与增强选择

### 5.1 主流默认方案

在文本 RAG 中，常见默认选择是：

```text
Embedding 模型生成向量 → 使用 cosine distance 或归一化后的 dot product 检索 → Top-K/Rerank
```

原因是这种方式与大多数文本语义 Embedding 的使用习惯匹配，面试和工程认可度都较高。

### 5.2 特定场景增强方案

| 场景 | 可选度量 | 说明 |
|------|----------|------|
| 向量已归一化 | dot product / inner product | 归一化后点积与余弦排序等价，计算效率可能更好 |
| 坐标、传感器、连续数值特征 | L2 距离 | 绝对空间距离有明确物理含义 |
| 高维稀疏特征或逐维差异敏感 | L1 距离 | 对单个维度的大偏差相对不如 L2 敏感 |
| 多模态向量 | 依模型说明选择 | 不同模型可能对 cosine、dot product、L2 的推荐不同 |

## 六、常见误区

**误区 1：文本 Embedding 永远只能用余弦相似度。**  
不绝对。很多模型推荐 cosine，但也有模型推荐 dot product；如果向量已归一化，dot product 与 cosine 排序等价。

**误区 2：距离值可以跨模型直接比较。**  
不同 Embedding 模型、维度和归一化方式会改变分数分布，阈值不能直接复用，需要重新评估。

**误区 3：相似度分数越高，答案一定越正确。**  
相似度只表示查询和文档片段的向量接近程度，不等价于事实正确性。RAG 中还需要 Rerank、上下文过滤和引用校验。

## 七、面试回答模板

> 余弦相似度、欧几里得距离和曼哈顿距离本质上是对“相似”的不同定义。余弦相似度关注向量方向是否一致，通常适合文本语义 Embedding；欧几里得距离关注多维空间中的直线距离，适合绝对坐标或连续特征有实际含义的场景；曼哈顿距离是各维度差值绝对值之和，适合逐维差异更可解释或高维稀疏特征场景。在文本 RAG 中，主流做法是使用 cosine distance，或者对向量归一化后使用 dot product。但具体选择应以 Embedding 模型说明、向量库支持和离线评测结果为准，不能把某一种距离度量绝对化。
