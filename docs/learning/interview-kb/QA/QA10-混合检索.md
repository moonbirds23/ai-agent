# 什么是混合检索？主要解决什么问题？

> 标签: RAG, 检索, 混合检索 | 难度: 🟡 中等 | 编号: QA10

---

## 一、核心定义

混合检索（Hybrid Retrieval）是将稠密检索（Dense Retrieval，例如向量相似度）和稀疏检索（Sparse Retrieval，例如 BM25、关键词、倒排索引）结合使用，再对多路候选进行融合排序的检索策略。

它的核心目标是：同时利用向量检索的语义泛化能力和关键词检索的精确匹配能力，减少单一路径的召回盲区。

```
用户查询
  ├─ 稠密检索：Embedding → 向量相似度 → 语义候选
  └─ 稀疏检索：BM25 / 关键词 → 精确候选
        ↓
合并去重 → 分数融合 / RRF → Rerank → 最终 Top-K
```

---

## 二、为什么需要混合检索

### 2.1 向量检索的局限

向量检索擅长语义相近的表达，但在以下场景可能表现不稳定：

- **专有名词和编号**：例如 `API-2024-B`、订单号、错误码、论文编号；
- **代码和符号**：例如函数名、类名、配置项、异常栈；
- **短查询**：用户只输入一两个词时，Embedding 语义信号不足；
- **版本和精确条件**：例如“2024 版”“v1.0.0”“Spring AI 1.0 GA”；
- **领域低频词**：Embedding 模型未充分学习的内部术语或缩写。

### 2.2 关键词检索的局限

关键词检索擅长精确命中，但也有明显不足：

- 无法处理同义表达，例如“无人驾驶”和“自动驾驶”；
- 对模糊描述能力弱，例如“那种未来感很强的夜晚城市”；
- 依赖分词、词典和大小写规范；
- 对跨语言表达不敏感，例如中文查“向量数据库”，英文文档写 `Vector Database`。

### 2.3 混合检索的互补性

| 检索方式 | 擅长 | 不擅长 |
|----------|------|--------|
| 向量检索 | 语义相似、模糊表达、同义改写 | 精确编号、代码符号、强关键词 |
| 关键词 / BM25 | 专有名词、标题、编号、精确词项 | 同义词、语义泛化、模糊描述 |
| 混合检索 | 同时覆盖语义召回和精确召回 | 工程复杂度和融合调参更高 |

因此，混合检索不是为了替代向量检索，而是为了让召回阶段更稳健。

## 三、主流实现流程

### 3.1 双路并行召回

```
query = 用户问题

Dense 路：
  query → embedding → vector search → denseTopK

Sparse 路：
  query → tokenize / BM25 → inverted index search → sparseTopK

融合：
  denseTopK ∪ sparseTopK → 去重 → 融合排序 → rerank → finalTopK
```

Dense 路通常用向量数据库或支持向量索引的数据库；Sparse 路通常用 Elasticsearch、OpenSearch、Lucene、PostgreSQL 全文检索或向量库内置 sparse 检索能力。

### 3.2 候选去重

同一文档可能同时被向量和关键词命中，需要按文档 ID、Chunk ID、URL、标题或内容 hash 去重。若同一文档多个相邻 Chunk 都命中，还需要考虑相邻 Chunk 合并或 MMR 去冗余。

### 3.3 融合排序

候选融合常见三类方法：

| 方法 | 说明 | 适用场景 |
|------|------|----------|
| 线性加权 | 将向量分、BM25 分归一化后加权求和 | 分数可解释且有评测集调权重 |
| RRF（Reciprocal Rank Fusion） | 只使用各路排名，不依赖原始分数量纲 | 多路分数不可比时的常用稳健方案 |
| Learning to Rank | 用标注数据训练排序模型 | 有点击日志、人工标注或高质量评测集 |

RRF 在工程中很常见，因为 BM25 分数和向量相似度的数值分布差异较大，直接相加容易失真。

RRF 公式：

```
RRF_score(d) = Σ 1 / (k + rank_i(d))
```

其中 `rank_i(d)` 是文档在第 i 个检索器中的排名，`k` 常取 60 左右，用来平滑排名差异。

## 四、与 Rerank 的关系

混合检索和 Rerank 不是同一个阶段：

- **混合检索**解决召回问题：让候选来源更全面，减少单路漏召回。
- **Rerank**解决精排问题：在候选集合中重新判断哪些最适合注入 Prompt。

常见生产链路是：

```
混合检索召回 Top-50
  ↓
RRF / 规则融合得到 Top-30
  ↓
Cross-Encoder Rerank 得到 Top-10
  ↓
MMR / 上下文压缩得到最终 Top-5
```

因此，混合检索通常是 Rerank 的上游。两者组合使用时效果更稳定。

## 五、工程落地要点

1. **先做强过滤再召回**：租户、权限、文档状态、时间范围等条件应尽可能前置过滤。
2. **两路 Top-K 不一定相同**：关键词路可针对专有名词取更小或更大的候选数，需按评测结果调整。
3. **分数不要直接相加**：BM25 和向量分数不在同一量纲，需归一化、RRF 或学习排序。
4. **记录每路召回来源**：便于分析某类问题是向量命中、关键词命中还是融合后命中。
5. **配合查询改写**：多轮问答中，先补全查询再混合检索，通常比直接检索当前短句更可靠。
6. **建立评测集**：用 Recall@K、nDCG、MRR、答案引用命中率评估融合策略，而不是只看主观样例。

## 六、常见误区

| 误区 | 更准确的说法 |
|------|--------------|
| 有向量检索就不需要关键词检索 | 向量检索对编号、专名、代码符号不稳定，关键词路径仍有价值 |
| 混合检索一定优于单路检索 | 在知识库简单、查询表达稳定时，单路检索可能已足够；混合检索会增加复杂度 |
| 两路分数可以直接加权 | 分数量纲不同，必须做归一化或使用 RRF 等排名融合方法 |
| 混合检索等于 Rerank | 混合检索偏召回，Rerank 偏精排，二者阶段和目标不同 |
| BM25 已经过时 | BM25 在专有名词、精确词项和短查询场景仍然非常有效 |

## 七、面试回答模板

混合检索是把向量语义检索和关键词或 BM25 检索结合起来的召回策略。向量检索擅长同义表达和模糊语义，但对编号、代码、专有名词和短查询不稳定；关键词检索擅长精确匹配，但不理解同义词和语义泛化。工程上通常会双路并行召回候选，先合并去重，再用 RRF、归一化加权或学习排序做融合，后面再接 Cross-Encoder Rerank 或 MMR 控制最终 Top-K。落地时要重点处理权限过滤、分数归一化、候选去重和可观测性，并通过 Recall@K、nDCG、MRR 和引用命中率评估融合效果。
