# 07 — 对象存储设计

## 为什么需要对象存储？

图片文件体积大（几百 KB ~ 几 MB），不适合存在数据库里：

| 存储方式 | 优点 | 缺点 |
|---------|------|------|
| 数据库 BLOB | 事务一致，管理简单 | 备份慢、扩容难、贵 |
| 对象存储 | 便宜、快、CDN 加速 | 需要额外服务 |
| 本地文件系统 | 零成本、简单 | 不能分布式、备份需手动 |

本项目选择 **对象存储抽象**：开发环境用本地文件，生产环境可切腾讯云 COS。

## 接口抽象

```java
public interface ObjectStorageService {
    StoredObject upload(byte[] data, String key, String contentType);
    byte[] download(String key);
    void delete(String key);
    String getUrl(String key);
}
```

## 双实现切换

```
                    ObjectStorageService (接口)
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
   LocalObjectStorageService    CosObjectStorageService
      @Profile("!cos")             @Profile("cos")
      默认启用                      预留桩
```

通过 Spring `@Profile` 注解实现零代码切换：
- 不指定 profile → `!cos` 激活 → 本地存储
- 指定 `--spring.profiles.active=cos` → COS 激活

## 本地存储实现

```
存储根目录: gallery-data/images (可配置)
文件路径:   {root}/gallery/{userId}/{pictureId}/origin.{ext}

示例: gallery-data/images/gallery/1/42/origin.png
```

**关键操作**：
- `upload()`：创建父目录 → `Files.write()` → 返回 StoredObject
- `getUrl()`：从 key 中提取 pictureId，返回 `/api/gallery/files/{pictureId}`
- `delete()`：`Files.deleteIfExists()`，文件不存在时静默忽略

**已知问题**：
- `getUrl()` 返回的是相对路径，`RedisChatMemory.toMessage()` 中 `new URL(relativePath)` 会抛 MalformedURLException。需要补全 baseUrl。
- 异常被包装为通用 `RuntimeException`，而不是 `BusinessException`，导致全局异常处理器返回 59999 泛型错误。

## COS 预留实现

所有方法抛出 `UnsupportedOperationException("COS 上传尚未实现")`。`getUrl()` 如果配置了 `baseUrl`，则返回 `baseUrl + key`。

## 存储 Key 设计

```
gallery/{userId}/{pictureId}/origin.{ext}
```

- `userId`：预留多用户扩展（当前为 1）
- `pictureId`：数据库主键，全局唯一
- `ext`：原始文件扩展名（png/jpg/webp）

## StoredObject

```java
public record StoredObject(
    String key,         // 存储路径
    String url,         // 访问 URL
    String contentType, // MIME 类型
    long size           // 文件大小（字节）
) {}
```

## 配置

```yaml
app:
  storage:
    local:
      root: gallery-data/images    # 本地存储根目录
    cos:
      secret-id: ${COS_SECRET_ID}
      secret-key: ${COS_SECRET_KEY}
      region: ap-guangzhou
      bucket: ai-agent-xxx
      base-url: https://xxx.cos.ap-guangzhou.myqcloud.com
```

## 安全注意

`CosConfig` 中的 `secretId` 和 `secretKey` 应标记 `@ToString.Exclude`，防止日志泄漏。API Key 通过环境变量注入，不入库。
