# 03 — 图片分析流程（mode=image_analysis）

## 触发条件

`ChatRequest.mode = "image_analysis"`，且请求中带有图片（imageBase64 或 imageUrl）。

## 完整数据流

```
用户上传一张图片，要求分析
     │
     ▼
PictureApp.handleImageAnalysis(request, chatId)
     │
     ├─ ① 校验图片存在
     │     if (request.imageBase64() == null && request.imageUrl() == null)
     │       → throw BusinessException(ErrorCode.PARAMS_ERROR, "图片分析模式需要上传图片")
     │
     ├─ ② autoSaveToCacheGallery(request)
     │     └─ 图片以 CACHE 位置入库 (StorageLocation.CACHE)
     │       SHA-256 去重 → GalleryPicture 元数据
     │
     ├─ ③ visionAnalysisService.analyze(imageBytes)
     │     │
     │     ▼
     │  调用 glm-4.5v 多模态视觉模型
     │    请求: { model: "glm-4.5v",
     │            messages: [{ role:"user",
     │              content: [ {type:"text", text:"请分析这张图片..."},
     │                         {type:"image_url", image_url:{url:"data:image/png;base64,..."}} ]}]}
     │    响应: 结构化视觉分析 JSON
     │      {
     │        subject: "主体描述",      // 画面中有什么
     │        scene: "场景类型",        // 室内/室外/自然/城市
     │        style: "艺术风格",        // 写实/插画/油画/水墨
     │        colors: ["#色值", ...],   // 主色调
     │        composition: "构图方式",   // 中心/三分/对称
     │        lighting: "光影描述",     // 自然光/逆光/柔光
     │        mood: "氛围情绪",         // 温暖/冷峻/梦幻
     │        imagePrompt: "生图用提示词" // 可直接用于生图
     │      }
     │
     ├─ ④ 将分析结果存入 ChatMemory
     │     └─ 不走 ChatClient（不经过 Advisor 链）
     │        手动 chatMemory.add(conversationId, userMessage)
     │        手动 chatMemory.add(conversationId, assistantMessage)
     │        助理消息内容: VisionAnalysisResult.memoryText()
     │          = "分析结果:\n" + detailText()
     │
     └─ ⑤ ChatResponseVO.imageAnalyzed(chatId, result)
          返回: { type:"image_analyzed", message:"分析完成", ...分析详情 }
```

## VisionAnalysisResult 结构

```java
public record VisionAnalysisResult(
    String subject,       // 主体描述
    String scene,         // 场景类型
    String style,         // 艺术风格
    String colors,        // 主色调
    String composition,   // 构图方式
    String lighting,      // 光影描述
    String mood,          // 氛围情绪
    String imagePrompt,   // 可直接用于生图的提示词
    String message        // 模型原始完整回复
) {
    public String detailText() {
        // 结构化呈现："【主体】xxx\n【场景】xxx\n..."
        // 用于展示给用户
    }

    public String memoryText() {
        // 用于存入 ChatMemory
        // "分析结果:\n" + detailText()
    }
}
```

## 为什么分析结果要手动存入 ChatMemory？

不走 ChatClient + Advisor 链的原因：
1. 分析模式不需要 Advisor 链的增强（无需 RAG 注入、无需 Prompt 优化）
2. 手动存入可以精确控制存入的内容（`memoryText()` 格式）
3. 避免经过 ContentGuard 的二次校验

## 分析模式在 RAG 中的作用

分析结果是图片 AI 画像（`PictureAiProfile`）的数据来源：
- 上传图片到图库 → 自动调视觉分析 → 写入 `picture_ai_profile` 表
- 画像的 `indexText` 字段拼接了图库元数据 + 视觉分析结果
- `indexText` 通过 `embedding-2` 向量化后存入 pgvector
- 后续 RAG 检索时，用户的需求文本向量与这些画像向量做相似度匹配
