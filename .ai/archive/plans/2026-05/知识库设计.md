# 知识库（Knowledge Layer）设计方案 V1

## 核心原则

**V1 只验证一件事：RAG 是否真的提升生图质量。**

砍掉所有远期能力，只保留最小闭环：

```
图片入库 → embedding → similaritySearch → 拼 prompt → 生图
```

---

## V1 删除清单

| 删除 | 理由 |
|------|------|
| `QueryRewriter` | 多一次 LLM 调用 ≈ +2s，V1 用原始 query 直接搜 |
| `QuestionAnswerAdvisor` 自动注入 | V1 手动拼 prompt，流程可见、好调试 |
| 多 `AssetType`（TEXT / PDF / …） | V1 只有 IMAGE |
| `SourceType` 枚举 | V1 不需要区分来源 |
| `Visibility`（PRIVATE / TEAM / PUBLIC） | V1 单用户，无权限概念 |
| `metadata` Map | V1 字段固定，不需要扩展性 |
| `FilterExpression` 元数据过滤 | V1 纯向量，不过滤 |
| `QueryRewriter` | 同上，V2 再加 |

---

## V1 架构（极简版）

```
┌────────────────────────────────────────┐
│  PictureApp.handleGeneration()         │
│                                         │
│  ① knowledgeService.semanticSearch()    │
│  ② 手动拼 prompt                        │
│  ③ DeepSeek → CogView-4                │
└──────────────┬─────────────────────────┘
               │
               ▼
┌────────────────────────────────────────┐
│  KnowledgeService                       │
│                                         │
│  add()         入库                     │
│  semanticSearch()  搜索                 │
│  remove()       删除                    │
└──────┬──────────────┬──────────────────┘
       │              │
       ▼              ▼
┌─────────────┐ ┌──────────────────────┐
│ AssetStorage│ │ VectorStore           │
│ (本地文件)    │ │ (SimpleVectorStore)   │
└─────────────┘ └──────────┬───────────┘
                           │
                    ┌──────▼───────────┐
                    │ EmbeddingModel    │
                    │ (OpenAI 兼容 API) │
                    └──────────────────┘
```

**就三层：文件、向量、门面。** 没有 SQLite 元数据表、没有 QueryRewriter、没有 Advisor 自动注入。

## 核心领域对象（极简版）

```java
public record KnowledgeAsset(
    String id,              // UUID
    String userId,          // V1 hardcode "default"
    String title,           // 标题
    String description,     // 语义描述 → embedding 的输入
    List<String> tags,      // 标签
    String storageUrl       // 图片文件路径
) {}
```

**对比初版砍掉的字段：**

| 砍掉 | 理由 |
|------|------|
| `AssetType type` | V1 只有图片 |
| `String thumbnailUrl` | V1 用原图 |
| `SourceType sourceType` | 不需要区分来源 |
| `Visibility visibility` | 单用户 |
| `float[] embedding` | 由 Spring AI Document 管理 |
| `Map<String, Object> metadata` | 字段固定 |

## 组件定义

### 1. AssetStorage — 文件存取

```java
public interface AssetStorage {
    StoredAsset store(InputStream input, String fileName, String contentType);
    InputStream load(String key);
    void delete(String key);
}

public record StoredAsset(String key, String url) {}
```

**V1 唯一实现：** `LocalAssetStorage`
- 路径：`./kb-data/{userId}/{assetId}.{ext}`
- 启动时自动创建目录

### 2. VectorStore — Spring AI 提供

不需要写代码。一个 `SimpleVectorStore` Bean：

```java
@Bean
VectorStore knowledgeVectorStore(EmbeddingModel embeddingModel) {
    return SimpleVectorStore.builder(embeddingModel).build();
}
```

### 3. EmbeddingModel — Spring AI 提供

用已有的 OpenAI 兼容 API（DeepSeek 或 OpenAI 的 embedding endpoint）：

```yaml
# application.yml
spring:
  ai:
    openai:
      api-key: ${DEEPSEEK_API_KEY}
      base-url: https://api.deepseek.com/v1
      embedding:
        enabled: true
```

如果 DeepSeek 没有 embedding API，换 OpenAI `text-embedding-3-small` 或 DashScope。

### 4. KnowledgeService — 门面

```java
@Component
public class KnowledgeService {

    private final AssetStorage assetStorage;
    private final VectorStore vectorStore;
    private final VisionAnalysisService visionService;

    // ── 入库 ──
    public KnowledgeAsset add(AddKnowledgeRequest request) {
        // 1. 下载图片 → assetStorage.store()
        // 2. Vision 分析 → title + description + tags
        // 3. 构建 Document → vectorStore.add()  ← 自动 embedding
        // 4. 构建 KnowledgeAsset 返回
    }

    // ── 语义搜索 ──
    public List<KnowledgeAsset> semanticSearch(String query, int topK) {
        // 1. vectorStore.similaritySearch(query, topK)
        // 2. Document → KnowledgeAsset 转换
        // 3. 返回
    }

    // ── 删除 ──
    public void remove(String assetId) {
        vectorStore.delete(assetId);
        assetStorage.delete(assetId);
    }
}
```

**不需要 SQLite。** `KnowledgeAsset` 的字段全部存入 `Document.metadata`，搜索返回时从 metadata 重建。V1 重启后知识库数据丢失可以接受（SimpleVectorStore 在内存中）。

## V1 两条链路

### 链路 1：图片入库

```
前端上传图片 → Vision 分析 → 展示结果 → 用户点"加入知识库"
  → POST /api/knowledge/add
  → KnowledgeService.add()
      ① ImageDownloadService.download(imageUrl)  → InputStream
      ② AssetStorage.store(input, name, type)    → ./kb-data/default/{id}.webp
      ③ VisionAnalysisService.analyze(image)     → title, description, tags
      ④ Document.builder()
             .id(assetId)
             .text(description)
             .metadata("title", title, "tags", tags, "storageUrl", storageUrl)
             .build()
      ⑤ VectorStore.add(document)                → embedding + 内存写入
      ⑥ 返回 KnowledgeAsset
```

### 链路 2：生图 + RAG

```
用户: "帮我生成温暖的日式卧室", mode=image_generation
  → PictureApp.handleGeneration()
      ① List<KnowledgeAsset> refs =
             knowledgeService.semanticSearch("帮我生成温暖的日式卧室", 5)

      ② 手动拼 prompt:
         if (!refs.isEmpty()) {
             augmentedMsg = """
                 [参考风格]
                 %s
                 [用户需求] %s
                 """.formatted(
                     refs.stream()
                         .map(a -> "- " + a.description())
                         .collect(Collectors.joining("\n")),
                     request.message()
                 );
         }

      ③ chatClient.prompt()
             .user(augmentedMsg)
             .advisors(...)
             .call()
             .entity(outputConverter)
         → ImageAgentResponse

      ④ ImageGenerationService.generate()  → CogView-4 生图

      ⑤ 返回 ChatResponseVO
```

**RAG 核心代码不超过 15 行。** 不用 Advisor，不用自动注入，手动拼接 prompt 一目了然。

## 后续阶段（V1 验证通过后）

| 阶段 | 加什么 | 触发条件 |
|------|--------|----------|
| V2 | `QueryRewriter` + SQLite 持久化（重启不丢） | 验证 RAG 有效后 |
| V3 | 混合搜索 + `FilterExpression` + metadata filter | 知识库规模 > 100 |
| V4 | 多用户 + 权限 + Agent Memory | 迁移 Picture-Backend 时 |
